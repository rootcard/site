How it works

Everyday simple. Cryptographically yours.

For you it is a username, a password and a card in a drawer. Under the hood, every step is a signature anyone can check.

Create

Pick a username and a password. Your browser makes a recovery key and prints it as a recovery card. Your id is the SHA-256 of a statement signed by that key, shown to people as Astra#3F9C.

Choose a home

The recovery key signs an instance: a fresh account key and the server that is your home. Here that is rootcard.org, so you need no server of your own.

Sign in

Your device proves the password to fetch the vault, unlocks it locally and signs the home's one-time challenge. The password never leaves your device.

Prove

Any service, on any server, can ask you to sign a challenge and check it against your public log. It does not call a central API and does not trust your home's word.

Download and move

Download your whole account as one file at any time. With the recovery card, move it to another home in minutes; your id, handle and password come along.

Recover

Forgot the password or lost a device? The recovery card signs a new instance. Every old password, vault and session stops working at once. Your id stays.

Two power levels

The password is for every day. The card is for everything else.

The format itself enforces the split: only the recovery key can sign changes to who can access the identity, where it lives or whether it exists.

Two ways to use it

A safer login for your service. One identity for many.

A standard username-and-password login

Add rootcard to your own server and your users see what they already know: a username, a password and, once, a recovery card to save. Your server becomes the host with rootcard-host (Rust); your pages use the npm package. No redirect, no third party, no password database to leak.

For developers

Two libraries and one HTTP binding.

Rust and JavaScript implement the same functions and produce the same bytes, checked against shared test vectors. The JavaScript package has zero dependencies and runs on WebCrypto in browsers and Node 20+. A host never sees a password, never runs Argon2id and verifies logs incrementally.

Questions

Good to know

Does rootcard.org keep a copy of my account?

Yes. As your home it keeps the public log, the public profile and the encrypted vault. It cannot decrypt the vault and cannot reset your password. You can download the whole account as one file at any time.

What happens if I lose the recovery card?

The identity keeps working with your password, but it can no longer be reset or moved. If you then also forget the password, the identity is gone. Nobody, rootcard.org included, can recover it: that is the point.

What if rootcard.org disappears?

With the recovery card your id and handle survive on any other host. With the card and a downloaded account file, everything moves: private data, profile and passwords.

Why is the key tool a file I download?

The recovery key is never typed into a page a server delivers live, because that server could change the page. The key tool is a single HTML file from the npm package that you open from your own disk. It talks only to the hosts you enter.

Can services link my accounts?

Every service gets its own proof, valid only for that service. If you do not want services to link your accounts, create several identities: they cannot be linked by their public data.

Is it ready?

rootcard is published and usable, but pre-1.0: the format is a draft and has not had an external security review. Use it to try things and for low-value accounts, not yet for anything you cannot afford to lose.
